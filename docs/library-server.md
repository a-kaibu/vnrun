# 複数タイトルの配信

現在の開発サーバーは１作品を起動時に前処理し、`/game/` から配信する。vnrun は複数作品と個別のセーブを自身で管理する必要がある。

作品フォルダを直下に並べたライブラリを追加し、各フォルダ名を作品 ID として `/games/<ID>/` に既存プロトコルを提供する。一覧・作品への要求で新しいフォルダを検出し、SDRS 等の前処理とエンジン検出を済ませてから公開する。セーブはライブラリ用のセーブルートの `<ID>/` に保存する。単一作品の `--game` も引き続き使える。

別案は作品登録用 DB と明示的な登録 API である。任意の場所の登録や名称変更には向くが、個人利用では登録 DB の管理とファイル移動時の整合性が増える。フォルダを発見源にする方式はデータ移動が分かりやすく、同一名の別作品を区別するには利用者が別名を付ける必要がある。

作品の追加中に検出すると前処理が失敗する場合がある。失敗した作品は配信せず、一覧に理由を表示し、後の要求で再試行する。ID を変更するとセーブの場所も変わるため、自動的には移動しない。外部を指すシンボリックリンクはライブラリの作品として受け入れない。前処理は作品のディレクトリを変更するため、同じ作品の同時登録を直列化する。

今後の判断として、任意の場所の登録、タイトルの編集、セーブのバックアップ・復元、アクセス制御は実際の運用を基に決める。前者２つは DB の要否、後者２つは保存・公開範囲の要件が必要で、今回のディレクトリ発見と既存プロトコルの実装は妨げない。大規模な同時利用における登録遅延や、書き込み途中の作品を検出した場合の挙動は実データで検証する。
